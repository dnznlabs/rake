# M03 — Hardening and deploy readiness

Status: not started · updated 2026-10-26

Everything that has to be true about the contracts before they touch a public network: every open
question about `src/Distribution.sol` ruled and the accepted changes landed, an independent review of
the code as it will ship, its findings dispositioned in `SECURITY.md`, the two measurements M01 left
open closed (`PUSH_GAS`, the practical table size), and a runbook that puts the factory, the
implementation and DNZN's own distribution at one address on every target chain. It comes after M02
because the review reads `App` and the chunk upload as well as `Distribution`, and after Phase 5
because a UI change after the review is a second review (`ROADMAP.md` § Order, decision 14). It
comes before M04 because M04 executes the runbook, and a runbook that has not been rehearsed is a
list of guesses.

**The sequencing is the point of this document.** Every candidate change to the primitive is ruled
before the reviewer reads a line, so the review reads the code that ships and reads it once. A
change accepted after the review re-opens the review; a change to the `snapshot()` struct re-opens
M02's t01–t05 as well (M02 § Phase 5 § Consequences 1). Phase 1 therefore has no engineer task: it
is a set of rulings, and nothing in Phase 2 starts until the ruling it depends on is recorded or its
deadline has passed and the default stands.

  the first provider limit bites. App-only, outside the review's scope, and it does not change what
  the review reads. Listed under § Carried issues at close-out for the relabel.
- The owner-declared token list ([#75](https://github.com/dnznlabs/rake/issues/75)) as a contract
  change — unless D3 rules it in. The recommendation is that it stays off the contract.
- ERC-1363 `transferAndCall`, ERC-777, streaming, vesting, conditional recipients — the overview's
  non-goals and `ROADMAP.md` § Not on the roadmap. D9 asks the question once so the review's scope is
  explicit; the recommendation is no.
- A second, external review. It is D1's option and a spend; if ruled in, it is scheduled by that
  ruling, and if it is scheduled after this milestone it is recorded here as M05's go/no-go input,
  not as an open criterion.
- Name resolution exercised, the `web3://` gateway, the widget on a real host — **M04**.
- Any change under `app/` beyond what an accepted ABI addition forces (D2's accept-ownership surface)
  and the docs claims it touches. The dapp is signed off; Phase 2 touches it only to follow the ABI.
