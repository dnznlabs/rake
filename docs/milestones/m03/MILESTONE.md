## Phases

In order; each phase's criteria are the next one's preconditions. Phase 1 is rulings, not tasks.
Phase 2's tasks run in the order listed because t02 takes t01's figures and t03 takes t02's ABI.
Phase 3 starts only when `src/` is final: the reviewer reads the merge commit of the last Phase 2 PR

## One-way doors

None that leaves anvil: no transaction in this milestone reaches a public chain. Three doors are
*fixed* here and *closed* later, and they close in this order:

1. **The runbook fixes the factory's address on every chain, forever.** Deployer, salt and the
   factory's init code — which is the compiler settings in `foundry.toml`, `solc 0.8.34`, `via_ir`,
   `optimizer_runs = 1000`, `cancun`, and every byte of `Distribution.sol` — together decide one
   address, and the implementation's with it (`new Distribution{salt: 0}` inside the constructor is
   itself CREATE2 from the factory). After M04's first deploy, a one-byte change to the primitive is
   a new factory at a new address with no old distribution following it (decision 5). This milestone
   is the last point at which that is free. The door closes on Sepolia in M04 and on Ethereum in M05.
2. **The deploying EOA (D13) is part of DNZN's address.** Decision 10: lose the key and the address
   can never be reproduced on a chain that does not have it yet. Named here, used in M04, protected
   from then on.
3. **The `snapshot()` struct is the sticky door, as in M01 and M02.** D2 and D3 are the two rulings
   that could open it, and both recommend against; if either opens it, M02 t01–t05 are re-run and
   this file's criterion 2 is reworded by the ruling before the code moves.

`App.lock()` is not a door this milestone approaches: the runbook deploys `App` unlocked and
criterion 6 proves the word appears only where it says it is not sent.
